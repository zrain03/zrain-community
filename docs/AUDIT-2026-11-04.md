# Zrain Community: Audit dan pengintegrasian Golden Reference (2026-11-04)

## Skop / Scope

BM: Audit berdasarkan ZIP `zrain-community.zip`, library `zrain-ui(2).zip`, dan Zrain Ultimate Engineering Master (edisi penyatuan bertarikh 2026-11-04, masih ditanda *Draf Penyatuan*). Perubahan memfokuskan konsistensi header/footer/navigasi, metadata, dokumentasi, kebersihan release dan ujian. Tidak mengubah API Worker, migration D1, product IDs, Turnstile, moderation, quota, comment embed atau konfigurasi hosting.

EN: Audit used the supplied Community and shared UI archives and the 2026-11-04 consolidated engineering master (marked *Consolidated Draft*). Changes target header/footer/navigation consistency, file metadata, documentation, release hygiene and tests. Worker API, D1 migrations, product IDs, Turnstile, moderation, quotas, comment embed and hosting config are left intact.

## Penemuan / Findings

| Severity | Penemuan / Finding | Tindakan / Action |
|---|---|---|
| Medium | Semua halaman penuh belum menggunakan shared UI source terbaru. / Full pages did not import the latest shared UI. | Copy exact `@zrain/ui` files into the static hosting assets; mount branding only. |
| Medium | `developer-dashboard.html`, `guidelines.html`, `privacy.html` dan `product.html` tidak mempunyai footer identity wrapper seragam. / Footer identity wrappers were inconsistent. | Normalize wrapper while keeping footer links. |
| Medium | Menu utama tersembunyi di viewport <=850px pada sebahagian halaman. / Primary navigation was hidden on narrower screens. | One horizontal, keyboard-accessible, touch-scrollable navigation across all full pages. |
| Low | Dua menu mobile lama menduplikasi pautan halaman utama dan admin. / Redundant mobile navigation duplicated links. | Retire unused `<details>` menus. |
| Low | Header/footer asal mempunyai ukuran berbeza daripada Golden Reference. / Old layout dimensions differed from Golden Reference. | Match reference sizing without redesigning sections or forms. |
| Medium | Tiada registry metadata/provenance yang menyeluruh. / Comprehensive provenance registry was missing. | Add `FILE_PROVENANCE.json` and inspect all retained files. Unknown creation dates are not invented. |
| Medium | Arkib input mengandungi cache tempatan, dependency dipasang, dan local development vars. / Uploaded archive includes local caches, installed dependencies and dev environment vars. | Exclude all of these and local SQLite data from the release; retain only source and safe `.dev.vars.example`. No data is deleted from user's original archive. |

## Batasan / Boundaries

BM: Menu seksyen utama milik Community dikekalkan supaya keadaan hero tidak tersalah highlight. Library digunakan untuk identiti rasmi sahaja; ScrollSpy Community mengendalikan klik/scroll dengan respons segera dan tanpa timer buatan. `embed.html` sengaja tidak diberi header/footer kerana ia ialah widget untuk laman lain.

EN: Community owns its section navigation so the hero never highlights a nonvisible section. Shared UI handles official identity only. Community's ScrollSpy handles instant click/scroll states without artificial timers. The iframe-only `embed.html` intentionally has no header or footer because it is embedded in other sites.

## Release / Penerapan

1. Place the source under `Zrain/Projects/zrain-community` as the project, with a safe backup/commit of the current working tree.
2. Compare with existing tracked files before applying: preserve local secrets, D1 binding IDs, and any changes newer than the uploaded archive. Do not overlay `.dev.vars`, `.local` or `node_modules` from ZIP.
3. From project root in PowerShell: `npm run check` and `npm run preflight:production`.
4. If the sibling shared project exists at `Zrain/Projects/zrain-ui`, you can run `npm run ui:sync` to refresh official CSS and JS; then rerun `npm run test:ui` and inspect the diff before deployment.
5. Only after local approval, deploy static site through existing Firebase project settings; Worker and migrations do not require a UI-only redeploy.
6. Smoke test each visible page at desktop/mobile, verify comments and admin isolation using real production credentials locally held by the operator, and prepare rollback from the previous known-good commit.
